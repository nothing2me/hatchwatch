# NestTrace Dashboard: Full-Stack Redesign

Date: 2026-10-09
Status: Approved in brainstorming, pending written-spec review

## 1. Intent

**Stated by the user**
- The current `dashboard/` (Vite + React, sample data) looks generic. Redo the whole UI/UX with the best available tooling.
- Use Next.js / React. Make it fully functional: database, server, client.
- End-to-end features: upload and auto-track, manage zones and cameras, alerts workflow, login and roles.
- Video on only one camera (the one it was uploaded to), real zoom in/out, collapsible legend.
- Visual direction: **A · Night Watch** (dark, full-bleed satellite map, floating glass panels, amber accent).
- Runtime: Docker Compose. Architecture option 1 (Next.js monolith + Postgres + Python worker).
- Worker runs the turtle tracker **and** the NestTrace detector.

**Assumed (confirmed implicitly through section approvals)**
- Audience: IslanderHack 2026 judges and beach-monitoring staff/volunteers.
- Success: the app looks purpose-built rather than templated; an admin can upload a clip, watch it process, see the calibrated track and alerts on a satellite map, and review alerts. All of this survives a restart.

**Non-negotiable boundaries (from `agent.md`)**
- Dashboard never imports from `web/`, calls the research API (`scripts/server.mjs`), or reads `*/private` or evaluator truth.
- Detector alert wording is exactly **"Digging activity detected; nesting unresolved."** No software path labels anything a confirmed nest.
- Frozen experiment files (`config/frozen.json`, `config/registration.json`, `config/settings.json`, `pipeline/*`) are not modified.

## 2. Architecture

Location: `dashboard/` (replaces the current Vite app).

```
dashboard/
  docker-compose.yml
  .env.example
  README.md
  web/        Next.js 15 app (UI + API + auth + Prisma)
  worker/     Python 3.12 job worker (tracker + detector adapter)
```

Services in `docker-compose.yml`:

| Service | Image / build | Role | Port |
|---|---|---|---|
| `db` | `postgres:16` | Postgres, named volume `pgdata` | internal 5432 |
| `web` | `dashboard/web` | Next.js UI, route handlers, server actions, Prisma, Auth.js; runs `prisma migrate deploy` and seed on start | 3000 |
| `worker` | `dashboard/worker` (build context = repo root, to copy `pipeline/` files) | Claims and runs jobs | none |

Shared volume `media`, mounted at `/media` in `web` and `worker`:
- `/media/uploads/<uuid>.<ext>`: original uploads
- `/media/derived/<videoId>/`: `trace.mp4`, `thumb.jpg`, `frame0.jpg` (calibration frame), detector outputs

Ports and environment variables stay separate from the research app (5173/5174). Env (`.env.example`): `DATABASE_URL`, `AUTH_SECRET`, `MEDIA_ROOT=/media`, `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, `MAX_UPLOAD_MB=500`.

## 3. Data model (Prisma, Postgres)

- `User`: `id`, `email` (unique), `passwordHash` (argon2), `name`, `role` (`ADMIN` | `VIEWER`), `createdAt`.
- `Zone`: `id`, `code` (unique, e.g. `B`), `name`, `outline` (JSON GeoJSON Polygon, `[lng, lat]`), `activityLevel` (`LOW` | `MEDIUM` | `HIGH`).
- `Camera`: `id`, `code` (unique, e.g. `B1`), `zoneId`, `lng`, `lat`, `headingDeg`, `fovDeg`, `status` (`ONLINE` | `OFFLINE`), `calibration` (JSON, nullable: `{ pairs: [{px:[x,y], lngLat:[lng,lat]}] x4, frameWidth, frameHeight, rmseM }`).
- `Video`: `id`, `cameraId`, `path`, `originalName`, `durationS`, `fps`, `width`, `height`, `uploadedById`, `createdAt`.
- `Job`: `id`, `videoId`, `status` (`QUEUED` | `RUNNING` | `DONE` | `FAILED`), `stage` (`probe` | `calibrate` | `extract` | `detect` | `track` | `render` | `persist`), `progress` (0–1), `attempts`, `error`, `heartbeatAt`, `createdAt`, `updatedAt`.
- `Track`: `id`, `videoId`, `points` (JSON `[{t, px, py, lng?, lat?}]`), `startT`, `endT`, `geoReferenced` (bool), `label`.
- `Alert`: `id`, `videoId`, `cameraId`, `zoneId`, `kind` (`DIGGING` | `TRACK_ONLY` | `NO_TURTLE`), `message`, `score` (nullable), `lng`/`lat` (nullable), `radiusM`, `startT`, `endT`, `status` (`NEW` | `REVIEWED` | `DISMISSED` | `FIELD_CONFIRMED`), `outsideCalibratedArea` (bool), `createdAt`.
- `AlertNote`: `id`, `alertId`, `userId`, `body`, `createdAt`.
- `AlertStatusChange`: `id`, `alertId`, `userId`, `from`, `to`, `createdAt`.
- `AuditLog`: `id`, `userId`, `action`, `targetType`, `targetId`, `details` (JSON), `createdAt`.

Messages by kind:
- `DIGGING`: "Digging activity detected; nesting unresolved." (exact)
- `TRACK_ONLY`: "Crawl tracked; digging not observed."
- `NO_TURTLE`: "No turtle tracked."

Status transitions: `NEW → REVIEWED → DISMISSED | FIELD_CONFIRMED`; `REVIEWED → NEW` allowed (reopen). `FIELD_CONFIRMED` means a person verified on the beach. The UI labels it "Field-confirmed by <name>", never "nest confirmed" generated by software.

## 4. Screens and UX (Night Watch)

Stack: Tailwind CSS v4, shadcn/ui (Radix primitives), Lucide icons, Motion, TanStack Query, MapLibre GL JS (via `react-map-gl/maplibre`), Esri World Imagery raster tiles + a labels overlay. Fonts: Inter (UI), JetBrains Mono (numbers and timecodes). Dark navy base, translucent blurred panels, a single amber accent reserved for attention states. Panels become bottom sheets under 768 px width.

### `/` Map (primary)
- Full-bleed satellite map. Zoom via +/− buttons, scroll, pinch. "Fit beach" button. Right-drag tilt/rotate. Layer toggles: zones, cameras, tracks, alerts.
- Top bar: logo, location, cameras online (n / total), active alert count, nav (Map, Alerts, Setup for admins), user menu.
- Left glass panel (collapsible): alerts feed, newest first, filter chips (status, zone). Clicking an alert flies to it and loads its video in the playback bar.
- Right glass panel (on camera select): camera code and facing, video player **only if the camera has a processed video**, otherwise a status card (online/offline, "No footage yet"). Shows zone, status, calibration fit (m), latest event.
- Bottom playback bar: play/pause, timecode, scrubber with alert tick marks, speed (0.5×, 1×, 2×), video selector for the camera. Drives the video element and the map turtle marker from one clock.
- Legend (collapsible; state saved in `localStorage`, with a try/catch fallback): zone activity colours, camera, track (travelled solid amber, full route dashed), start dot, last-seen pin, alert radius.
- Map layers: zone polygons with code labels, camera symbols and view cones, tracks, start/last-seen pins, moving marker, alert circles (radius `radiusM`).

### `/alerts`
Table with filters (status, zone, camera, kind, date). Row opens a drawer: clip starting at `startT`, mini map, score and evidence explanation, status buttons (admins), notes, status history.

### `/settings` (admins)
- **Zones:** list; draw or edit a polygon on the map; name, code, activity level.
- **Cameras:** list; place on map; drag heading; FOV; status. **Calibrate:** pick 4 points on the camera's latest `frame0.jpg`, then 4 matching map points. Shows the projected ground outline preview and the RMSE in metres. Saving requires 4 non-collinear pairs.
- **Upload:** drag-drop a video, choose a camera, submit. Live job progress (stage + bar), error text and **Retry** on failure, link to the result on the map when done.

### `/login`
Email + password (Auth.js credentials provider, JWT session). Seeded admin from env.

### Permissions
- `VIEWER`: read-only on all pages except `/settings` (hidden, and the server returns 403).
- `ADMIN`: everything. All mutations go through server-side role checks and write `AuditLog`.

## 5. API surface (Next.js route handlers / server actions)

- `POST /api/videos` (admin, multipart): validate extension (`.mp4`, `.mov`), MIME sniff, size ≤ `MAX_UPLOAD_MB`. Stream to a server-generated path. In one transaction create `Video` + `Job(QUEUED)`, then `NOTIFY job_update`.
- `GET /api/videos/:id/stream`: range-request video streaming from `/media` (original or `trace`). Authenticated.
- `GET /api/media/:videoId/:file`: thumbnails and frames, allow-listed filenames only.
- `POST /api/jobs/:id/retry` (admin): `FAILED → QUEUED` if `attempts < 3`.
- `GET /api/events`: SSE. The server `LISTEN`s on `job_update` and `alert_update` and forwards `{jobId, status, stage, progress}` / `{alertId}`.
- Zones, cameras, alerts, notes: server actions with zod validation and role checks.
- All reads use Prisma from server components or TanStack Query against small `GET` handlers.

## 6. Worker

`dashboard/worker/` contents:
- `main.py`: loop. Every 2 s claims one job with `UPDATE job SET status='RUNNING' ... WHERE id = (SELECT id FROM job WHERE status='QUEUED' ORDER BY created_at FOR UPDATE SKIP LOCKED LIMIT 1) RETURNING *`. Heartbeat every 5 s. On startup, re-queues `RUNNING` jobs with `heartbeatAt` older than 2 min (`attempts += 1`; `FAILED` if attempts ≥ 3).
- `stages.py`: the stage functions below.
- `geo.py`: lng/lat ↔ local ENU metres around the zone centroid; homography from 4 pixel↔ground pairs; RMSE.
- `tracker.py`: dashboard-owned turtle tracker, generalised from the prototype. Dark connected component on the ground region, nearest-neighbour continuity, `MAX_JUMP` scaled to frame size, thresholds in a config file.
- `adapter.py` (`ADAPTER_SCHEMA = "adapter-v1"`): the **only** module that touches the copied detector code. It builds detector calibration JSON (`reference_points` in the detector's ±8 × ±6 m frame, centred on the zone centroid), runs `extract.py` as a subprocess, stages `detect.py`, `common.py`, `signals.npz`, `calibration.json`, `settings.json` in a fresh temp directory, runs detection there, and returns the `full` method candidates converted back to lng/lat.
- `vendor/`: `extract.py`, `detect.py`, `common.py`, `settings.json` copied from the repo root at image build time. A recorded SHA-256 manifest is checked at startup; on mismatch the worker refuses to start.

Stages (each updates `Job.stage`/`progress` and `NOTIFY job_update`):
1. **probe:** ffprobe (imageio-ffmpeg). Reject duration < 4 s or undecodable. Store fps, size, duration. Write `frame0.jpg`.
2. **calibrate:** if the camera has calibration, build the homography and the detector calibration; otherwise mark the job pixel-only.
3. **extract + detect:** only if calibrated (the detector needs ground calibration). Uses the adapter.
4. **track:** run the tracker. Project points to lng/lat if calibrated.
5. **render:** `trace.mp4` (H.264 yuv420p, `+faststart`) with box and trail; `thumb.jpg`.
6. **persist:** one transaction writes `Track`, `Alert` rows (`DIGGING` per detector `full` candidate; `TRACK_ONLY` if a track exists and no `DIGGING`; `NO_TURTLE` if no track), then `DONE`, `NOTIFY job_update` and `alert_update`.

Errors:
- Any stage exception: `FAILED`, `error = "<stage>: <message>"`, video kept, admin Retry.
- Uncalibrated camera: pixel track stored, `geoReferenced=false`, no detector run. The UI shows "Calibrate camera to place on map".
- Detector candidate outside the ±8 × ±6 m frame: `outsideCalibratedArea=true`, shown with a warning.

Stated limitations (shown in the UI's info popover and the README):
- Map positions are approximate: the turtle body is above the sand (parallax), and a 4-point calibration has fit error.
- Detector scores are not probabilities. The detector was validated only on synthetic daylight video.

## 7. Seed data

- Admin user from env. One `VIEWER` demo user (`viewer@nesttrace.local`, password printed by seed in dev only).
- Zones A–D and cameras A1–D2 converted from the current `sampleData.js` pixel positions to lng/lat. This uses the map image's geographic bounds, derived once from OpenStreetMap for the Holiday Beach, Port Aransas extent, and recorded in the seed script. A2 starts `OFFLINE`.
- No videos are seeded. The demo flow uploads the turtle clip to B1 live.

## 8. Testing

Worker (pytest):
- `geo`: round-trip pixel → lng/lat → pixel within 0.1 m on synthetic pairs; ENU conversion; rejects collinear pairs.
- `tracker`: on a short checked-in clip, tracks every frame and the end point is within tolerance.
- `adapter`: runs on `examples/A-clean-11` public signals with the vendored detector and returns candidates; the vendor manifest check fails on a tampered file.
- Job claim: two concurrent claimers never get the same job (`SKIP LOCKED`).
- Stale-job recovery and the attempts limit.
- Each stage's failure sets `FAILED` with the stage name.

Web (Vitest):
- Role guard: every mutation returns 403 for `VIEWER`.
- Alert status transition table; no software-generated "confirmed nest" text anywhere (grep test over `web/`).
- Upload validation: extension, size, generated path (no user-controlled path segments).

End-to-end (Playwright, against Compose):
- Admin login → upload the clip to B1 → SSE progress reaches `DONE` → track and pin visible on the map → scrubbing moves the marker → change alert status → history shows it.
- Zoom buttons change map zoom; legend collapse persists across reload.
- Viewer login: Setup is hidden and the direct URL returns 403.

Boundary test: fails if any file under `dashboard/` imports or references `../web/`, `scripts/server.mjs`, port 5174, or `private/` paths.
